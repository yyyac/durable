# Windows 目录交互检查

## 自动化覆盖

`tests/native-directory-picker.spec.ts` 经浏览器驱动真实前后端、pi-durable 和隔离 SQLite，仅替换外部模型服务，验证：

- 目录菜单同时显示系统选择和手填入口；
- 取消手填保留原会话、消息草稿与工作区列表；
- 含中文、单引号和美元符号的路径经过正式信任与绑定流程后，可调用真实 read 工具读取文件，模型收到真实结果。

`tests/workspaces.spec.ts` 另覆盖无效路径、工作区复用、Windows 大小写和 junction 别名、父子目录、历史持久化及目录失效拒绝。

系统选择器没有测试占位实现。自动化不替换选择器返回值，也不把网页目录上传视为本机目录选择。

## 本机能力探测

2026-11-06 已在本机非交互加载系统 PowerShell 5.1 的 WinForms 组件，确认 `FolderBrowserDialog` 可实例化、线程为 STA，随后释放对象；没有显示窗口。生产适配使用系统 PowerShell 的固定脚本和编码参数，隐藏控制台，选中路径仅作为 JSON 数据返回。

## 尚未完成的原生走查

本次环境的 Windows 控制连接返回 `Computer Use native pipe is unavailable`，以下检查未执行，不能视为通过：

- 在目录菜单选择“选择文件夹…”，确认真实系统窗口可见且获得焦点；
- 选择已有目录后显示原路径，确认信任后创建会话并读取文件；
- 取消系统窗口不创建工作区、会话或目录关联，原位置与消息草稿保持可用；
- 重复选择已绑定目录复用原工作区，仍沿用正式信任与路径校验；
- 系统选择器启动失败时显示明确错误，并可继续手填路径；
- 从页面打开工作目录，确认 Windows 资源管理器显示正确的实际目录。

走查应使用专门的临时目录，不打开、修改或清理个人工作区。
