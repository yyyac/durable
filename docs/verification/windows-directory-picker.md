# Windows 目录交互检查

## 自动化覆盖

`tests/native-directory-picker.spec.ts` 经浏览器驱动真实前后端、pi-durable 和隔离 SQLite，仅替换外部模型服务，验证：

- 目录菜单同时显示系统选择和手填入口；
- 取消手填保留原会话、消息草稿与工作区列表；
- 含中文、单引号和美元符号的路径经过正式信任与绑定流程后，可调用真实 read 工具读取文件，模型收到真实结果。

`tests/workspaces.spec.ts` 另覆盖无效路径、工作区复用、Windows 大小写和 junction 别名、父子目录、历史持久化及目录失效拒绝。

系统选择器没有测试占位实现。自动化不替换选择器返回值，也不把网页目录上传视为本机目录选择。

## 本机能力探测

2026-11-06 已在本机非交互加载系统 PowerShell 5.1 的 WinForms 组件，确认 `FolderBrowserDialog` 可实例化、线程为 STA，随后释放对象；没有显示窗口。生产适配使用系统 PowerShell 的固定脚本和编码参数，隐藏控制台，选中路径仅作为 JSON 数据返回。

## 原生人工结果

2026-11-06，在隔离验收页由用户操作 Windows 窗口并反馈：

- 原生文件夹弹窗正常；
- 选中文件夹后，网页的绝对路径输入框会自动填入；
- 点击目录路径入口，资源管理器能打开正确文件夹。

本次 Windows 控制连接返回 `Computer Use native pipe is unavailable`，因此上述结果来自用户人工反馈，不能声称由自动化控制了系统窗口。隔离页的公开接口另确认已创建工作区会话。

## 启动失败与手填回退

在另一独立验收后端完成初始化后，仅将该进程的 `SystemRoot` 指向不存在目录，实际触发选择器可执行文件启动失败；没有修改系统设置或正常验收页。

网页显示“无法打开 Windows 文件夹选择器，请填写文件夹路径或稍后重试”。随后通过同一表单手填准备好的临时目录、确认信任并创建工作区成功。该检查未替换选择器返回值，也未增加产品测试开关。

## 覆盖边界

系统窗口选中、关闭及路径回填由人工反馈覆盖；路径校验、重复目录、草稿保留、真实文件读取和持久化由浏览器整体测试覆盖。没有把手填路径自动化称为系统窗口自动化，也未单独制造 Windows 组件加载异常或权限拒绝；选择器启动失败已由真实缺失可执行路径覆盖。
