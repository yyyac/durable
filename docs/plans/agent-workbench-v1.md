# 个人 Agent 工作台首版

## 当前阶段

首版正式应用已按 [GitHub Issue #1](https://github.com/yyyac/durable/issues/1) 实施，九张子票据已合入集成分支 `feat/agent-workbench-v1`。工作台具备真实流式回复、思考与 Markdown 阅读、多会话管理、多服务三协议配置、主动停止、失败重试及重启恢复。原型阶段已取消，运行与检查方式见仓库根目录的 README。

完整规格见 [个人 Agent 工作台首版规格](../specs/personal-agent-workbench-v1.md)。

## 已确认范围

- 使用 `@earendil-works/pi-durable` 构建后端 Agent，提供前端 Web 页面。
- 首版供个人在本机使用，不加入登录、多人账号或公网部署。
- 首版完成思考内容与正文的流式回复，不考虑工具调用。
- 思考内容仅取自模型接口实际返回的可见思考；不支持或未返回思考内容时，仅显示正文。
- 思考按参考站原样默认折叠，点击可展开查看；生成中显示“思考中…”与计时，思考结束后保留“思考过程”与耗时。正文始终直接展示，支持 Markdown 与代码块复制。此规则取代此前讨论的“生成时展开、完成后自动折叠”。
- 页面以 `http://127.0.0.1:58766/` 为视觉与交互参考；保留首版聊天页面的完整布局，超出首版的功能及入口直接移除，不预留占位或禁用入口。
- 侧栏只有会话，不引入文件夹或工作区；提供新建、切换、重命名、搜索、归档会话，历史在刷新页面或重启后端后保留。
- 设置页允许保存多个模型服务及各自的模型列表；每个服务配置接口地址、API Key 与接口协议，每个模型配置名称、模型 ID 及是否支持思考。
- 聊天输入框旁可切换模型；切换只影响后续回复，保留当前会话历史。
- 自定义模型服务支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 三种接口协议。
- 切换会话或刷新页面不停止后台生成；返回会话后接续显示。后端重启后恢复未完成任务。同一会话生成时禁止重复发送，不同会话可并行生成。
- 主动停止后保留已收到的思考与正文并标注“已停止”；这段未完成的助手回复不进入下一轮模型上下文。
- 产品名称使用“个人 Agent 工作台”，替换参考页的 Kimi Code 名称与标识。
- 不制作原型，直接依据参考站与正式规格实施。原先讨论的页面状态转为正式功能与验收范围，不再保留原型制作及验收步骤。
- 已获准在参考站新建独立的纯聊天测试会话，用于观察真实思考与正文的流式展示；不进行文件或工具操作，不改动已有会话。
- 技术栈采用 React + TypeScript + Vite 前端，Node 24 + TypeScript + Hono 后端，pi-durable + SQLite 管理会话及任务。开发时前后端分别运行；交付时由后端同时提供页面与接口，使用一个本机地址。
- 界面采用 CSS Modules + CSS 变量，按需使用 Radix UI Primitives 和 Lucide。
- 前后端采用 REST + SSE：REST 处理发送、停止、会话管理和设置；SSE 订阅当前状态与后续更新。
- 任务执行与网页连接分别管理。关闭网页只取消订阅；停止任务必须调用明确接口。重连后先同步当前状态，再继续接收更新。
- 会话与任务由 pi-durable 存入 SQLite。模型配置和 API Key 由后端保存在本机配置文件中，Key 明文存储；该文件不进入 Git，设置页保存后仅展示脱敏值。
- 后台最终判定回复失败后，保留已显示内容、标注失败原因，并提供手动重试。网页连接断开时自动重连并同步状态，不重新提交问题。

## 已确认技术方案

| 层次 | 技术选择 | 职责与理由 |
| --- | --- | --- |
| 前端 | React + TypeScript + Vite | 页面、会话操作、设置、思考与正文展示；前端热更新与 Agent 进程分开。 |
| 样式与交互 | CSS Modules + CSS 变量，按需使用 Radix UI Primitives 和 Lucide | 直接校准参考页面细节，同时复用菜单、弹层的键盘与焦点行为。 |
| 后端 | Node 24 + TypeScript + Hono | 持有长寿命 Harness，处理命令、状态订阅和模型配置，交付时同时提供前端静态页面。 |
| Agent 与持久化 | pi-durable + SQLite | 会话记录、任务和实时生成状态由运行时管理；前端不维护第二套权威会话记录。 |
| 模型配置与凭据 | 后端本机配置文件 | 模型配置与 API Key 明文保存，排除于 Git；前端保存后只接收脱敏摘要。 |
| 前后端通信 | REST + SSE | REST 发命令，SSE 观察状态；连接断开不停止生成，重连获取当前快照。 |

兼容性依据：[React 官方](https://react.dev/learn/build-a-react-app-from-scratch)、[Vite 官方](https://vite.dev/guide/)、[Hono Node 适配](https://hono.dev/docs/getting-started/nodejs)、[Hono SSE](https://hono.dev/docs/helpers/streaming)、[CSS Modules](https://vite.dev/guide/features#css-modules)、[Radix](https://www.radix-ui.com/primitives/docs/overview/introduction)、[Lucide](https://lucide.dev/guide/react/getting-started)。经验证的依赖版本固定在 `package.json` 与 `package-lock.json`，运行环境为 Node 24。

## 正式实现与验收

直接实现正式应用并接入真实 Agent。自动化测试可使用可控的上游模型测试服务驱动流式状态，工作台本身使用真实前后端与 pi-durable 持久化；不新增面向用户的模拟演示模式。

后端持久化、任务恢复、真实协议交互与页面视觉均纳入正式功能验收。浏览器测试使用隔离 SQLite 和可控上游，并通过真实进程终止与重启验证恢复。

两轮纯聊天的观察已完成，见 [参考站流式展示记录](../research/reference-chat-streaming.md)。用户已确认按原站复刻思考默认折叠的交互。

### 功能与视觉验收清单

以下清单依据已确认的范围整理，供整体复核：

- 在相同视口下对照参考站截图检查侧栏、聊天区、输入框、菜单和设置弹层的布局、间距、字体、颜色与图标；应用已确认的名称替换及功能删减。
- 验证空会话、思考生成中、正文生成中、完成、已停止、请求失败与未配置模型状态。
- 思考默认折叠，可手动展开查看实时追加内容；无思考时只显示正文，思考状态与计时遵循参考站。
- 正文按片段增长，展示 Markdown、代码块与复制操作；处于跟随状态时随回复增长向下滚动。
- 可操作会话新建、切换、重命名、搜索与归档；只有会话列表，无文件夹或工作区。
- 可操作模型服务与模型列表设置，在输入框旁选择模型；配置由后端本机文件持久化。
- 同会话生成中禁止重复发送；停止、失败提示与手动重试均可正常使用。
- 验证网页断开只取消订阅，重连先同步当前状态再持续更新，以及后端重启后历史与未完成任务的恢复。
- 超出首版的功能和入口直接移除，不展示占位或禁用入口。

## 已核实的实现事实

- 仓库已包含 React 前端、Hono 常驻后端、真实 pi-durable 与 SQLite，以及覆盖规格主要行为的浏览器测试。
- pi-durable 可通过 `conversation.watch()` 提供历史记录与包含思考、正文的部分生成状态；最终答案由运行时自动追加。
- 可见思考依赖模型接口是否返回对应内容，不能从 token 计数或加密签名还原。
- 模型配置与命令准入在同一运行时事务中完成；停止针对捕获的任务标识，避免并发命令影响另一轮回复。
- 思考计时作为独立显示元数据由后端观察并保存，和网页订阅生命周期分离；消息内容仍以运行时记录为唯一来源。

调研依据见 [pi 组件研究](../research/pi-packages.md)。
