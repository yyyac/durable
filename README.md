# 个人 Agent 工作台

基于 React、Hono 和 pi-durable 的本机工作台。由常驻后端持有 Agent，浏览器通过 REST 发送消息、SSE 观察状态；关闭浏览器不会取消生成。

平台使用蓝色回环 D 标志。发送或重试消息后，等待首段可见内容时显示同一标志和“请求中…”提示；出现思考或正文、请求失败或主动停止后提示消失。

## 运行

需要 Node.js 24 和 npm。

```sh
npm ci --ignore-scripts
npm run build
npm start
```

打开 `http://127.0.0.1:3100`，左下角“设置”首先展示自定义供应商列表，点击“添加供应商”或已有供应商卡片进入配置表单。填写服务名称、接口地址、API Key 和协议；保存后返回列表，取消或返回列表会丢弃当前草稿。编辑页也可删除供应商。支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages；每个服务可添加多个模型，分别填写模型 ID、上下文大小、最大输出（`maxTokens`）、显示名与“支持思考内容”标记。上下文和最大输出的单位均为 tokens，必须为正整数，最大输出不能超过上下文；旧配置缺少这些参数时，默认采用上下文 `131072`、最大输出 `16384`，最大输出同时受上下文大小约束。只有接口实际返回可见思考文字时，页面才展示思考区。

OpenAI 接口地址通常包含服务要求的前缀，例如 `https://api.example.com/v1`；Anthropic 使用服务基址，由协议适配器追加 `/v1/messages`。已保存的密钥在输入框内显示固定黑点，接口不返回密钥或尾号；编辑时留空会保留原密钥，输入新密钥后保存会替换原值。已有单模型配置文件可直接继续使用，下一次保存时转为多服务格式。

在输入框旁打开模型菜单可切换模型。选择只影响后续回复，生成中的请求及已有会话历史保持原样；未配置可用模型时，先到设置中添加模型。

模型名称左侧的圆环显示当前会话的上下文占用，悬停或通过键盘聚焦可查看 token 用量、所选模型的上下文大小和占用比例。优先使用最近一次回复的实际用量；后续消息、生成中的内容以及缺少用量的回复采用模型库估算，浮层以“约”标识。切换到不同模型时，历史用量也按估算显示。

侧栏可新建和切换会话，悬停会话后的菜单提供重命名与归档。归档会从当前列表移除记录，历史仍保留；点击“搜索”或按 `Ctrl+K` 可按名称找到并打开会话，包括已归档的记录。搜索中可用方向键选择、Enter 打开、Esc 关闭。

每个普通会话自动获得数据目录下独立的 `sessions/<会话 ID>` 工作目录，旧会话也会保留历史并分配目录。新会话页输入框上方和聊天标题区域显示实际路径，点击可通过 Windows 资源管理器打开。目录关联跨刷新和重启保留；已分配目录被移动或删除时显示不可用，保留历史与原路径，不自动重建旧目录。

新会话页的工作目录菜单提供“选择文件夹…”和“填写文件夹路径…”：前者通过系统 PowerShell 调用真实 Windows 文件夹选择器，选中后仍需确认本机工具访问说明；两种入口使用相同的目录校验和工作区复用流程。取消系统选择器不会创建记录，系统选择失败时可继续手填路径。浏览器自动化与原生系统窗口的验证边界见 [Windows 目录交互检查](docs/verification/windows-directory-picker.md)。

开发时运行 `npm run dev`，访问 Vite 输出的地址。Vite 将 `/api` 请求转发到后端，默认端口 3100，也会跟随 `PORT` 指定的端口。正式运行由后端在同一地址提供页面和接口。

`PORT` 可修改后端端口；`WORKBENCH_DATA_DIR` 可指定数据目录，默认是当前工作目录的 `.data`。该目录保存 SQLite 会话与任务、`models.json` 模型配置；API Key 以明文保存，整个目录已排除于 Git。请保留数据目录以继续使用已有会话，避免让多个后端进程同时打开同一目录。

后端重启后会由 pi-durable 恢复未完成任务，网页自动重连后继续观察。恢复可能重新请求中断的上游生成；已经完成的回复不会重新生成。

每个普通会话拥有保存在工作台数据目录下的独立工作目录，页面可查看路径并打开本机文件夹。首次点击“启用本机工具”时会展示本机访问说明；确认前仍可纯聊天，确认后所有普通会话复用该选择。工具使用后端进程的用户权限，工作目录并非目录沙箱。目前开放真实文件读取、新文件创建、已有文件覆盖和精确编辑；目标父目录须已存在，新文件使用独占创建防止同名覆盖。修改已有文件前须在当前会话成功读取；读取后内容发生变化则返回冲突，模型需重新读取。检查和修改按实际文件协调，目录别名、父子工作区和硬链接不会绕过保护；这不代表对命令、外部编辑器或多个进程提供文件系统事务隔离。精确编辑保留 UTF-8 BOM 和原有 CRLF/LF 换行，拒绝模糊匹配、重复文本及重叠范围。模型调用、参数、输出和状态会按顺序出现在消息流中，可展开查看。读取中断后可自动恢复；中断的写入与编辑持久等待用户逐次确认重试或停止，等待时释放运行名额但暂停该会话后续执行，确认继续重新检查原文件版本、目录和全局名额，不会因确认而覆盖变化后的文件。停止保留已经产生的文件改动和输出，不会撤销。已完成调用不会因重启再次执行。目录移动或删除后不会自动重建旧目录，也不会回退到后端启动目录。

思考耗时由常驻后端按可见内容块出现和结束记录，刷新、切换或关闭页面不会重置，已完成的耗时随历史保留。这是宿主观察到的时间，不代表模型内部精确计算时长；旧历史没有计时记录时不会补造耗时。

## 检查

```sh
npm run typecheck
npm run build
npx playwright install chromium
npm test
```

浏览器测试自动启动隔离的真实后端、pi-durable 和临时 SQLite，只将外部模型服务替换为可暂停的本机流式服务。测试使用独立端口和临时数据目录，不读取个人配置。已有 Chromium 时可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定可执行文件。
