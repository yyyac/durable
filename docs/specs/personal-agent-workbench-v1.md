# 基于 pi-durable 的个人 Agent 工作台首版

后续工作区与工具能力的范围扩展见 [GitHub Issue #11](https://github.com/yyyac/durable/issues/11)。本文保留首版范围记录；涉及工作区和工具的后续行为以该议题为准。

## Problem Statement

个人用户需要一个能在本机日常使用的 Agent 工作台，通过熟悉的 Web 聊天界面管理会话、配置自己的模型服务，并持续看到模型实际提供的思考内容与正文。目前仓库只有研究与领域文档，没有可运行的前后端应用。

用户希望页面按指定的 Kimi Code Web 参考站复刻，同时去掉文件夹、工作区和工具相关功能。刷新或关闭网页不应中断后台回复，重新打开后应恢复当前状态；用户主动停止时才取消生成。

## Solution

交付本机单用户使用的“个人 Agent 工作台”：前端 Web 展示与操作会话，常驻后端以 pi-durable 运行 Agent，并以 SQLite 保存会话和任务。通过 REST 处理命令、SSE 订阅状态，先同步当前快照，再持续显示更新。

直接实现正式应用，不制作原型。参考页面为 `http://127.0.0.1:58766/`，沿用其聊天布局、视觉、菜单和流式呈现方式；超出本规格的功能和入口直接移除。用户在设置页配置自己的模型服务和模型，首版完成真实的思考与正文流式回复，不支持工具调用。

## User Stories

1. 作为个人用户，我希望在本机打开一个地址即可使用工作台，以便通过 Web 页面与 Agent 交流。
2. 作为个人用户，我希望应用使用“个人 Agent 工作台”的名称和标识，以便将其识别为自己的工作台。
3. 作为个人用户，我希望侧栏、聊天区、输入框、菜单和设置弹层遵循指定参考页面的视觉，以便获得一致的使用体验。
4. 作为个人用户，我希望页面只展示首版可用的功能，以便操作时不会遇到占位或禁用的未来功能入口。
5. 作为个人用户，我希望侧栏直接列出会话，以便管理个人交流记录，而无需建立文件夹或工作区。
6. 作为个人用户，我希望新建会话，以便开始一个独立话题。
7. 作为个人用户，我希望切换会话，以便继续不同话题的交流。
8. 作为个人用户，我希望重命名会话，以便为记录使用容易识别的标题。
9. 作为个人用户，我希望搜索会话，以便找到需要继续或回顾的交流。
10. 作为个人用户，我希望归档会话，以便整理当前使用的会话列表。
11. 作为个人用户，我希望刷新页面后仍能看到历史消息，以便不会丢失交流记录。
12. 作为个人用户，我希望重启后端后保留会话历史，以便持续使用同一工作台。
13. 作为个人用户，我希望发送文本并得到所选模型的真实回复，以便完成一次正常交流。
14. 作为个人用户，我希望在同一会话中继续发送后续问题，以便模型结合此前有效对话回答。
15. 作为个人用户，我希望当前会话生成期间禁止重复发送，以便不会意外排队或启动重叠回复。
16. 作为个人用户，我希望不同会话可以同时生成回复，以便切换话题时无需等待另一个会话结束。
17. 作为个人用户，我希望正文随模型输出逐步出现，以便不用等待整段回复完成。
18. 作为个人用户，我希望查看模型实际返回的可见思考内容，以便了解接口提供的推理文字。
19. 作为个人用户，我希望模型不支持或未返回可见思考时只显示正文，以便不会看到伪造的思考或空的思考区。
20. 作为个人用户，我希望思考默认折叠且可以点击展开，以便按参考页面的方式控制内容密度。
21. 作为个人用户，我希望展开思考后能够看到持续追加的内容，以便观察仍在进行的回复。
22. 作为个人用户，我希望生成时看到“思考中…”及计时，思考结束后保留“思考过程”与耗时，以便判断当前进度。
23. 作为个人用户，我希望多个思考或正文片段按照真实输出顺序显示，以便不会出现内容错序、遗漏或重复。
24. 作为个人用户，我希望正文即时呈现 Markdown、列表、引用和代码块，以便阅读结构化回答。
25. 作为个人用户，我希望复制助手正文，以便将回答用于其它地方。
26. 作为个人用户，我希望单独复制代码块，以便方便使用回答中的代码。
27. 作为个人用户，我希望处于跟随状态时页面随回复增长向下滚动，以便持续看到最新内容。
28. 作为个人用户，我希望生成中能够主动停止回复，以便结束不再需要的模型请求。
29. 作为个人用户，我希望停止后保留已经收到的思考和正文并标注“已停止”，以便回顾已产生的内容。
30. 作为个人用户，我希望未完成的已停止助手回复不进入下一轮模型上下文，以便沿用已确认的运行时语义。
31. 作为个人用户，我希望切换会话时后台继续生成，以便稍后返回查看。
32. 作为个人用户，我希望刷新或关闭网页后任务仍在后台运行，以便网页连接不会决定任务是否完成。
33. 作为个人用户，我希望重新打开会话时先看到当前完整状态，再接收后续更新，以便恢复观察而不重放丢失的流片段。
34. 作为个人用户，我希望网络重连不会重新提交问题，以便不会收到重复回复或重复触发模型请求。
35. 作为个人用户，我希望只有明确的停止操作才取消当前任务，以便订阅断开不会误触停止。
36. 作为个人用户，我希望后端重启后恢复未完成任务，以便使用 pi-durable 提供的持久化执行能力。
37. 作为个人用户，我希望在设置页管理多个模型服务，以便使用自己的服务来源。
38. 作为个人用户，我希望为模型服务填写接口地址、API Key 和接口协议，以便连接自定义服务。
39. 作为个人用户，我希望选择 OpenAI Chat Completions、OpenAI Responses 或 Anthropic Messages 协议，以便接入已确认范围内的兼容接口。
40. 作为个人用户，我希望在每个模型服务下配置多个模型的名称、模型 ID 和思考支持标记，以便使用服务提供的不同模型。
41. 作为个人用户，我希望在聊天输入框旁切换模型，以便后续回复使用选中的模型，同时保留当前会话历史。
42. 作为个人用户，我希望重启后模型配置仍然存在，以便不用重复填写服务信息。
43. 作为个人用户，我接受后端在本机配置文件中明文保存模型配置和 API Key，以便完成首版配置持久化。
44. 作为个人用户，我希望保存后的设置页只显示脱敏的 API Key，以便回顾配置时不直接暴露完整凭据。
45. 作为个人用户，我希望尚未配置模型时看到明确状态和设置入口，以便知道如何开始使用。
46. 作为个人用户，我希望后台最终判定回复失败后保留已显示内容并展示失败原因，以便理解发生了什么。
47. 作为个人用户，我希望失败后能够手动重试，以便再次尝试获得当前问题的回复。
48. 作为个人用户，我希望网页连接断开时自动重连并同步后台状态，以便继续查看正在运行的回复。

## Implementation Decisions

- **前端模块**：采用 React、TypeScript、Vite。界面使用 CSS Modules 与 CSS 变量，按需使用 Radix UI Primitives 处理菜单、弹层和焦点交互，Lucide 提供图标。
- **后端模块**：采用 Node 24、TypeScript、Hono，以常驻进程持有 pi-durable Harness。开发期间前后端分别运行；正式使用时后端同时提供前端静态页面与接口，用户访问一个本机地址。
- **Agent 运行模块**：使用 `@earendil-works/pi-durable`，通过 pi-ai 连接模型服务。运行时管理会话、任务、历史记录与实时生成状态，SQLite 为会话与任务的持久化存储；前端只持有展示状态，不维护第二套权威记录。
- **命令与订阅模块**：REST 接口负责发送、停止、会话管理及设置。SSE 负责会话状态订阅。每次首次订阅或重连时先同步当前状态，再持续发送后续更新；不能仅依赖浏览器保存的旧事件游标恢复。
- **生命周期约束**：网页关闭、刷新、切换会话或 SSE 断开只解除订阅，不关闭 Harness 或取消任务。停止生成必须调用明确的后端命令。后端重启后重新打开持久化存储，由运行时恢复未完成任务。
- **提交约束**：同一会话正在生成时，前后端都拒绝重复发送；不采用运行时默认的输入排队行为。不同会话允许并行生成。订阅重连不得重新提交问题。
- **消息展示**：从运行时的实时消息内容读取思考和正文，保持内容块的顺序。思考文字只能来自模型实际返回的可见内容；token 计数、加密签名与正文推测都不能充当思考文字。
- **最终消息衔接**：生成结束时以持久化答案替换临时生成状态，补齐节流窗口中的尾部内容，避免答案重复或末尾缺失。最终答案由运行时自动保存，宿主不重复追加。
- **思考交互**：默认折叠，用户可以点击展开查看流式内容；生成中展示“思考中…”与计时，思考结束后展示“思考过程”与耗时。无思考内容时不展示空的思考区。此决定取代早期讨论中的“生成时展开、完成后自动折叠”。
- **正文交互**：正文即时渲染 Markdown，支持复制正文和代码块；处于跟随状态时自动滚动。流式期间未闭合的 Markdown 标记允许随后续片段补全；最终正文应正常呈现。
- **停止与失败**：停止时保留运行时已发布的部分思考与正文并标注“已停止”；已停止的未完成助手回复不进入后续模型上下文。后台最终判定失败后保留已显示内容、给出原因并允许手动重试。连接自动重连与模型回复重试分别处理。
- **会话管理模块**：提供新建、切换、重命名、搜索、归档和持久化历史。会话直接列于工作台，不引入文件夹、项目或工作区层级。
- **模型配置模块**：设置页管理多个模型服务及各自的模型列表。模型服务保存接口地址、API Key 和协议；模型保存名称、模型 ID 与思考支持标记。支持三种已确认协议，不将参考站特定模型的思考档位强行套用到所有服务。
- **模型切换**：输入框旁的模型选择只改变后续回复采用的模型，保留既有会话历史与当前已经执行的请求。
- **配置持久化**：模型配置和 API Key 由后端保存在本机配置文件中，Key 明文存储，配置文件排除于 Git。保存后向前端返回脱敏配置摘要。
- **视觉与范围**：以指定参考站的聊天页面、菜单和模型设置为依据，使用“个人 Agent 工作台”名称与标识。去掉文件夹、工作区及所有超出首版的功能和入口，不保留占位或禁用控件。
- **交付顺序**：取消原型制作与原型验收阶段，按本规格实现正式应用并进行功能和视觉验收。本次任务仅整理和发布规格，不启动应用开发。

## Testing Decisions

- **主测试边界**：以工作台对用户暴露的整体行为为一个主边界。通过浏览器驱动正式前端及真实后端；保持真实 pi-durable 和 SQLite，只将外部模型服务替换为可控的流式测试服务。测试服务是自动化测试依赖，不是产品中的演示模式。
- **好测试的标准**：断言可见内容、操作结果、持久化结果、模型请求次数和生命周期行为；不绑定 React 内部状态、私有函数、内部事件分发方式或特定组件拆分。避免为每个内部模块建立独立的模拟边界。
- **消息与流式行为**：覆盖无思考、思考与正文、多内容块、分段 Markdown、最后一个节流窗口和正常结束，验证顺序、默认折叠、展开后持续追加、计时展示、最终内容完整且只显示一次。
- **生命周期行为**：用可暂停、可继续的测试模型输出验证切换会话、刷新、关闭连接和重新订阅。检查任务仍在运行、重连先拿到当前状态、之后持续更新，且不会重复提交或产生第二次模型请求。
- **持久化与恢复**：使用隔离的真实 SQLite 数据，在后端重启后检查历史记录和未完成任务恢复。运行时可能重试重启前中断的上游请求，测试应按 pi-durable 的恢复语义验证最终结果，而非要求续接同一条上游 TCP 流。
- **并发与停止**：验证同会话重复发送在后端也被拒绝、不同会话可并行生成、显式停止后后台不再继续，部分内容保留且标注正确。通过后续模型请求验证已停止的助手片段不进入上下文。
- **模型设置与协议**：通过设置页保存多个服务和模型，并以可控测试服务覆盖三种协议的基本流式交互。验证模型切换只影响后续回复、重启后配置仍在、接口配置摘要脱敏，使用临时配置和虚拟 Key，避免接触用户凭据。
- **失败与重试**：区分订阅断开与模型最终失败，验证订阅自动恢复不会再次请求模型；模型失败会保留已显示内容并提供原因和手动重试。
- **会话行为**：通过界面验证新建、切换、重命名、搜索、归档，以及页面刷新与后端重启后的历史恢复。
- **视觉验收**：在与参考站相同的视口和固定内容下对照截图，检查侧栏、聊天区、输入框、菜单、模型设置，以及空会话、思考中、正文中、完成、停止、失败和未配置模型状态；明确应用名称替换、移除文件夹与范围外功能等已批准差异。
- **既有测试先例**：当前仓库没有应用代码或测试套件。上游 pi-durable 的真实模型、运行中途订阅及持久化示例可用作语义依据；本项目测试应围绕自己的外部行为建立，不复制上游内部测试。

## Out of Scope

- 原型、模拟演示产品或独立的原型验收阶段。
- 工具调用、文件操作、附件处理、改动或差异视图、权限模式、插件、子智能体及相关入口。
- 文件夹、项目、工作区及其层级管理。
- 登录、多人账户、公网部署和远程访问方案。
- WebSocket 通信，以及由网页连接断开隐式停止任务。
- 同会话输入排队、生成期间插入消息和参考站的排队快捷键。
- 将停止的未完成助手回复加入下一轮上下文或据此自动续写。
- 系统凭据管理器、API Key 加密存储或浏览器端完整凭据持久化。
- 未确认的高级模型原生参数，以及强制所有模型返回思考或套用相同思考档位。
- 新增视觉设计方向，以及与首版无关的参考站设置分类或未来功能占位。

## Further Notes

- 本规格使用“工作台、会话、模型服务、模型、思考内容、正文”的既有领域语言，并遵循已记录的“Agent 任务生命周期与网页订阅分离”架构决定。
- 用户已明确取消原型阶段；此前关于模拟数据原型的约定不再作为实施步骤。
- 参考站已进行两轮独立纯聊天实测，当前配置下思考全程默认折叠。两轮均先输出思考、后输出正文，但实现不能据此假设所有模型只采用这一顺序。
- 参考站支持生成中排队输入，本项目采用已确认的同会话禁止重复发送规则。这是有意保留的产品差异。
- 参考地址仅在本机可达；同机执行者可结合现有截图与观察记录进行复核。
- pi-durable 的 API 标注为实验性；研究基于 1.5.0，实施时应固定经验证的依赖版本，避免无意引入 API 变更。
- 规格发布使用 `ready-for-agent` 标签，不代表当前会话已经开始编写应用代码。
